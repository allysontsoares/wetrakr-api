# auth endpoints

Extracted from the WeTrakr docs app on 2026-10-01 (changelog 1.0.7). Each route is `https://api.wetrakr.com` plus the path. Send `wetrakr-api-version: 1`.

OAuth and external-id lookup. Flow and PKCE rules: `references/auth.md`.

Auth `oauth` requires `Authorization: Bearer`. `apiKey` requires `wetrakr-api-key`. `optionalOauth` works with the key; a token adds the caller's state. An empty auth on a direct object means the symbols line is the source.

## Index

- `GET /media/external/{source}/{external_id}` — Resolve an external id
- `GET /oauth/authorize` — Authorize
- `POST /oauth/device/code` — Generate device codes
- `POST /oauth/device/token` — Poll for the access token
- `POST /oauth/logout` — Log out
- `POST /oauth/token/refresh` — Refresh access token
- `POST /oauth/token` — Exchange authorization code

## GET /media/external/{source}/{external_id}

- Docs id: `media-external-lookup`
- Auth: `apiKey`
- Symbols: `apiKey`

Translate an id from another catalog into the WeTrakr id you need for every other endpoint. Sources: imdb, tmdb, tvdb and letterboxd (a slug, like the-dark-knight). IMDb ids starting with nm resolve to people.

### Path params

- `source` (string, required) — Catalog the id comes from, lowercase: imdb, tmdb, tvdb or letterboxd.
- `external_id` (string, required) — The id in that catalog.

### Query

- `type` (string, optional) — movie, show or person. Only TMDB reuses an id between a movie and a show: without type such an id answers 409 with both matches. The other sources do not need it.

### Responses

- **200** — The WeTrakr id and its type.
- **400** — Unknown source or malformed id.
- **404** — Nothing in the catalog carries that id.
- **409** — The id matches both a movie and a show. Repeat the call with type.

## GET /oauth/authorize

- Docs id: `oauth-authorize`
- Auth: `none`
- Symbols: `apiKey`

Send the user here to sign in and approve your app. This is a browser redirect, not a JSON endpoint. WeTrakr renders its own login page. On success the user is redirected back to your redirect_uri with a one-time authorization code.

### Query

- `client_id` (string, required) — Your application key.
- `redirect_uri` (string, required) — Where WeTrakr redirects after approval. Must match your app settings.
- `code_challenge` (string, required) — Base64URL-encoded SHA-256 of your PKCE code_verifier.
- `code_challenge_method` (string, required) — Must be S256.
- `state` (string, required) — Opaque value you generate to prevent CSRF. Verify it matches on the way back.

### Responses

- **302** — Redirect back to your redirect_uri with the authorization code and your state.
- **400** — code_challenge missing or not a valid S256 value (43 characters of Base64URL), code_challenge_method not S256, state missing, or a redirect_uri your app does not list. The token exchange also refuses a code issued without PKCE.

## POST /oauth/device/code

- Docs id: `oauth-device-code`
- Auth: `none`

Start the device flow. Show the `user_code` and the `verification_url` to the user, keep the `device_code` and poll for the token every `interval` seconds until `expires_in` runs out. Limited to 5 codes every 15 minutes per IP.

### Body

- `client_id` (string, required) — Your app key, from Settings, API.

### Responses

- **200** — New codes. `expires_in` and `interval` are in seconds.
- **401** — The `client_id` does not belong to any registered app.
- **423** — The app is suspended.
- **429** — Too many codes requested from this IP. Wait 15 minutes.

## POST /oauth/device/token

- Docs id: `oauth-device-token`
- Auth: `none`
- Symbols: `emitsToken`

Poll with the `device_code` at the `interval` you were given. While the user has not answered you get `400`; once they approve, you get the same access and refresh tokens as the authorization code flow. Stop polling on any other status.

### Body

- `code` (string, required) — The `device_code` from Generate device codes.
- `client_id` (string, required) — Your app key. Must be the one that generated the code.
- `client_secret` (string, optional) — Optional. Send it only from a server you control, never from an app users install. If you send it, it must be correct.

### Responses

- **200** — The user approved your app. Save both tokens; the code cannot be used again.
- **400** — Pending: the user has not answered yet. Keep polling.
- **400** — The body has no code (or device_code) or no client_id. It is a bug on your side, not a pending answer: read error and stop polling unless it is authorization_pending.
- **401** — The `client_secret` you sent is wrong.
- **404** — Unknown `device_code`, or it was generated by another app.
- **409** — Already used: the tokens for this code were already issued.
- **410** — Expired: the user did not answer in time. Start again.
- **418** — Denied: the user refused access.
- **429** — Slow down: you are polling faster than `interval`. Wait before the next poll.

## POST /oauth/logout

- Docs id: `oauth-logout`
- Auth: `oauth`
- Symbols: `oauth`

Revoke a refresh token and end the session. The access token is sent in the Authorization header.

### Body

- `refresh_token` (string, required) — The refresh token to revoke.

### Responses

- **200** — Session revoked.
- **401** — Missing or invalid access token.

## POST /oauth/token/refresh

- Docs id: `oauth-token-refresh`
- Auth: `none`
- Symbols: `emitsToken`

Access tokens expire after 7 days and refresh tokens after 180. Trade a valid refresh token for a fresh access token and a rotated refresh token. Store the new refresh token, the old one is retired after a short grace window.

### Body

- `refresh_token` (string, required) — The refresh token from a previous token exchange.

### Responses

- **200** — A new access token and a rotated refresh token.
- **400** — The request carries no refresh token.
- **401** — The refresh token is invalid, expired, revoked, was rotated more than a minute ago, or its user is disabled. The message says which. It will never work again: send the user through the authorize step.

## POST /oauth/token

- Docs id: `oauth-token`
- Auth: `none`
- Symbols: `emitsToken`

Exchange a one-time authorization code for an access token and a refresh token. Public clients prove ownership of the request with the PKCE code_verifier. Exchange the code immediately: authorization codes are single-use and short-lived.

### Body

- `client_id` (string, required) — Your application key.
- `code` (string, required) — The authorization code from the redirect.
- `code_verifier` (string, required) — The original PKCE verifier whose SHA-256 matches the code_challenge you sent to /oauth/authorize.
- `client_secret` (string, optional) — Only for apps that run on their own server. Omit it in mobile, desktop and browser apps, which are proved by PKCE alone. If you do send it, it is checked: a wrong secret answers 401 and burns the code.

### Responses

- **200** — Token issued.
- **400** — The code is invalid, expired, already used, or the code_verifier does not match.
- **401** — A client_secret was sent and it is not the one of that app. The code is burned: start the flow again.
